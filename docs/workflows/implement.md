# Prompt — Implementação

Leia `AGENTS.md`, `docs/project/requirements.md`, `docs/architecture/system-design.md`, os ADRs e o arquivo do incremento `docs/implementation/INC-XX-*.md`. Para qualquer interface ou fluxo visual, consulte `docs/design/README.md` e as especificações aplicáveis: `product.md`, `user-flows.md`, `design-system.md`, `frontend-guidelines.md` e telas em `docs/design/screens/`. Consulte `roadmap.md` para confirmar limites; itens futuros não entram no MVP sem aprovação explícita.

Implemente **somente** o incremento INC-XX seguindo Laravel, Inertia, React/TypeScript e as convenções existentes. Trate design como especificação da experiência, sem inventar capacidades de backend nem substituir regras funcionais. Se encontrar conflito material, registre-o e aguarde decisão antes de codificar a parte afetada. Antes de alterar arquivos, apresente um plano curto com arquivos afetados e ambiguidades. Em seguida implemente o menor conjunto coerente de mudanças, escrevendo testes pertinentes. Não introduza funcionalidades fora do escopo.

Para a interface, cubra os critérios de UX do incremento e, quando aplicável, estados de carregamento, vazio, erro e sucesso, acessibilidade básica e uso mobile/desktop. Siga as diretrizes frontend para componentes, tipagem e estilos; adicione bibliotecas de UI somente quando houver necessidade demonstrável. Não implemente itens do roadmap como melhorias futuras.

Ao terminar: liste arquivos alterados, requisitos atendidos, comandos executados, testes escritos/executados, decisões e riscos. **Não faça commit e não declare o incremento aprovado.** Aguarde autorização para revisão adversarial.
